# DiskPulse Phase G — Performance and Artifact-Size Report

Date: 2026-08-28

This report records the evidence-based optimization work performed in Phase G. It does not overwrite the earlier scan/AI latency report.

## Methodology

- Real-machine scan data is treated as mixed/warm cache and used only for end-to-end smoke validation.
- Controlled synthetic fixtures were used where repeated measurements matter.
- Artifact-size measurements are exact byte counts from local builds.
- Browser QA was performed with headless Chrome screenshots; this model could not visually inspect the screenshots, so verification also checked the embedded image bytes directly against the committed optimized asset.

## Optimizations retained

### RETAIN: Dedicated dashboard brand asset

The dashboard renders the brand image at 48×48 CSS pixels. The original source PNG is 1254×1254 and was embedded twice into every generated HTML file as Base64.

Change:

- Added `assets/DiskPulse-dashboard.png`, a 128×128 PNG generated with built-in Windows .NET `System.Drawing`.
- Changed `src/powershell/App.ps1` to read `assets\DiskPulse-dashboard.png` for the dashboard brand data URI.
- Changed `build-release.ps1` payload to include the dashboard asset instead of the large source PNG.
- Regenerated `check.bat`.

### RETAIN: None other

No scanner, persistence, AI, or HTML assembly changes were retained in Phase G.

## Optimizations rejected

- **Scanner hot-loop rewrite:** Rejected. No controlled benchmark identified a safe scanner change; prior evidence already rejected this direction.
- **Multi-disk concurrency:** Rejected again. No new evidence materially changes the previous conclusion.
- **AI worker restructuring:** Rejected. Prior evidence shows local worker startup is small relative to network/inference time.
- **HTML assembly optimization:** Rejected. Dashboard assembly/write remains in the millisecond range.
- **Persistence micro-optimization:** Rejected. Phase D atomic writes remain sub-second and reliability is more important.
- **Aggressive minification of PowerShell/C#/JS:** Rejected. Reviewability is more valuable than shrinking a ~276 KB runtime script.
- **NSIS compression change:** Not attempted. The installer is now small; no material benefit is expected.

## Measurements

### Scanner

- Scanner production code was not changed.
- Scanner-focused test runtime increased from ~251 ms to ~828 ms due to added filesystem fixtures, not scanner runtime changes.
- Real isolated scan completed in ~21.4 s on mixed/warm cache conditions; not treated as a controlled benchmark.

### Dashboard generation

- Report generation was reported by the real scan as ~0.189 s for full HTML assembly and write.
- No optimization was justified for this path.

### Persistence

- CSV publication: ~102 ms for 3,650 rows (from Phase D measurement).
- Event journal compaction: ~95–136 ms for 1,501 lines in Phase G retests.
- No persistence optimization was justified.

### Build/verification

- `scripts/build-check.ps1`: ~226 ms
- `build-release.ps1`: ~621 ms
- `build-installer.ps1`: ~293 ms
- Full canonical verifier including installer: PASS
